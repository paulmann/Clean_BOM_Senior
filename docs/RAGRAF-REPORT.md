### 1.1 Границы этого корпуса — замерено, не предположено

`ragraf.py init` осмотрел каталог и вернул:


**Ни `.ps1`, ни `.sh`, ни `.bat` в список языков не попали** — то есть два из трёх
файлов с кодом в этом проекте не индексируются вообще. Причина найдена в исходниках
RAGRAF, а не предположена:

| Факт | Где |
|---|---|
| Карта расширений → язык содержит только `.php .phtml .inc .md .sql .css .htm .html .js .mjs` | `RAGRAF\src\ragraf\config.py`, `LANG_BY_EXT` |
| Разбор деревом (AST) — только `php`, `css`, `html`; текстовые чанки — `markdown`, `sql`, `javascript` | `RAGRAF\src\ragraf\indexer.py:309,315` |
| `language_of()` возвращает `None` для неизвестного расширения, и файл отбрасывается как `skipped_not_included` | `RAGRAF\src\ragraf\config.py`, `indexer.py:318` |

**Вывод: RAGRAF здесь не мог статически разбирать ни PowerShell, ни shell.** Ни
`symbol`, ни `code`, ни `callers` по этим файлам не работают: единственное, что было
бы проиндексировано — `README.md` и `AGENTS.md` как markdown. `class_usage`,
`schema`, `table_usage`, `policy_trace`, `write_check` к этому проекту не относятся
(нет ни стилей, ни схемы БД, ни матрицы прав).

Корпус зарегистрирован и проиндексирован в этом объёме:

```
$ ... index
языки: javascript 2, markdown 2   include: **/*.js **/*.mjs **/*.md
```

## 2. Как на самом деле искались факты

Раз статический индекс по `.ps1`/`.sh` недоступен, требования §8 пришлось выполнять
буквально: **факт — это ссылка `файл:строка` либо замер**. Поэтому каждый дефект ниже
имеет либо номер строки, либо воспроизведённый прогон на изолированном наборе.

### 2.1 Два открытия о среде, найденные замерами

**`pwsh -Command` искажает аргументы и код выхода — измерено.** Это критично для
любого теста, который запускает порт.

| Способ запуска | Аргумент `-` доходит как | Код выхода при валидной ошибке |
|---|---|---|
| `pwsh -File script.ps1 -` | `-` | 2 |
| `pwsh -Command "& script.ps1 -"` | пустая строка | 1 вместо 2 |

Из-за этого ранняя батарея проверок CLI дала ложные результаты, и первый вариант
`tests/cli-contract.ps1` был неверен. Тест переведён на прямой `ProcessStartInfo` с
`ArgumentList` — без промежуточной оболочки.

**Утилита извлечения метки, написанная для отладки, обрезала метку на внутреннем
`goto`-ярлыке.** Два прогона на «сломанном» стенде показали дефект там, где его не
было. Правильный вывод: инструмент отладки тоже требует проверки на корректность.

## 3. Найденные дефекты и что с ними сделано

### 3.1 Порт `clean-bom-senior.ps1` — исправлено

#### Дефект A: `-` (одиночный дефис) не считался неизвестной опцией

* **Строка:** `clean-bom-senior.ps1:349` — `elseif ($argument.StartsWith('-') -and $argument.Length -gt 1)`
* **Эталон:** `clean-bom-senior.sh:477` — `case "$1" in … -*)` совпадает с одиночным `-`
* **Замер:** `bash reference.sh -` → `exit 2`, `Unknown option: -`;
  порт → `File not found: -`, `exit 0`. То же для `--dry-run -`.
* **Почему это важно:** вызывающий скрипт не мог отличить реализации друг от друга —
  расхождение в контракте, а не косметика.
* **Исправление:** условие `$argument.Length -ge 1 -and $argument[0] -ceq '-'`.
  Ошибка в первой редакции правки (`-gt 1`) исключала ровно нужный случай; поймана
  прогоном, а не чтением.

#### Дефект B: NUL-байт за пределами первых 8192 байт не обнаруживался → порча файла

* **Строка:** `clean-bom-senior.ps1:493` — `$buffer = [byte[]]::new(8192)`, одно чтение
* **Замер:** файл `BOM + 9000 'x' + NUL + CRLF` (9006 Б) → порт **перезаписал** его до
  9002 Б, вернув валидный на вид текст. Документация при этом обещает:
  «A file that carries a supported extension but holds a NUL byte is reported and
  skipped instead of being rewritten» (`README.md:635`).
* **Исправление:** новый `Find-NulByteOffset` — чтение блоками 64 КБ до конца файла.
  `Test-UnsupportedForContents` стал обёрткой над ним, поэтому один проход отвечает и
  на «бинарный ли», и на «где именно»; сообщение теперь содержит смещение.
* **Почему это худший класс дефектов:** инструмент сработал «успешно» и молча испортил
  файл в чужом проекте.

#### Дефект C: пути в логе абсолютные вместо `./имя`

* **Строки:** сообщения `Invoke-CleanFile` / `Invoke-DryRunFile`
* **Эталон:** обход через `find .`, поэтому печатает `./имя`; блок «Files That Would Be
  Processed» порта содержал `C:\Users\...\a.php`.
* **Почему это дефект, а не стиль:** README заявляет «same output»; лог порта и лог
  эталона не совпадали построчно.
* **Исправление:** `Format-DisplayPath` — путь относительно текущего каталога с
  префиксом `./`. Для аргументов командной строки относительная форма **отключена**
  (`-DisplayRelative $false`): эталон печатает их verbatim.

#### Замечание без правки: счётчик `size_errors`

`ErrorTypes['size']` (`clean-bom-senior.ps1:1030`) недостижим: переполнение по размеру
даёт skipped. В эталоне то же — `ERROR_TYPES["size"]` инициализируется в строке 104 и
печатается в 538, но ни один путь его не увеличивает (проверено поиском по файлу).
Строка вывода сохранена ради паритета, значение остаётся `0`. Не изменялось.

### 3.2 Эталон `clean-bom-senior.sh` — решения по каждому

| # | Дефект | Строка | Замер | Решение |
|---|---|---|---|---|
| 1 | `cleanup()` вызывает `find "$TEMP_DIR"` без кавычек: при `TMPDIR` с пробелом временные файлы не удаляются | `clean-bom-senior.sh:111` | `find $d …` при `d='/tmp/probe with space'` → `rc=1`; с кавычками → `rc=0` | **оставлено**, внесено в осознанные отличия |

## 5. Про `clean-bom-senior.bat`

Создан как третья реализация того же контракта. Полное описание —
`docs/BAT-PORT.md`; здесь только то, что относится к работе RAGRAF и к проверкам.

**Ключевое ограничение:** в `cmd.exe` нет байтового ввода-вывода, поэтому очистка
выполняется на шестнадцатеричном представлении через `certutil -encodehex 4` /
`-decodehex 4`. Обе стороны проверены байт-в-байт, включая короткую последнюю строку и
файл из трёх байт.

**Ловушки cmd, найденные замерами (не из памяти):**

| Ловушка | Замер | Следствие |
|---|---|---|
| `.bat` с LF-переводами не исполняется | `exit 255`, вывода нет | файл обязан быть CRLF — и этот инструмент сам его не чистит |
| Скобки в тексте внутри `if ( … )` ломают блок | сначала молчаливое прекращение обработки, затем `exit 255` после строки `PROCESSING` | сообщения со скобками выводятся из отдельных меток |
| `set /a` внутри блока | `* was unexpected at this time` (переменная подставляется до разбора блока: `set /a 5+=1`) | вся арифметика вынесена в метки с `call` |
| Возврат пустого значения через `:trim`-синтаксис | `set "C=" & set "T=!C:~6!"` → `T=[~6]` (литерал) | файлы из одного BOM обрабатываются отдельной ветвью |
| `for /r *.htm` матчит и `.html` по 8.3-имени | `mixed.html` попадал в список дважды и во второй раз логировался как clean | тот же класс, что `Get-ChildItem -Filter` в PowerShell |
| `%*` в вызываемой метке содержит свои аргументы | `INFO "INFO "msg""` | `%~2` вместо `%*` |
| `copy /b` перезаписывает время приёмника | `copy` → время источника; атрибуты и creation time сохраняются | время восстанавливает PowerShell, если он есть; иначе — предупреждение в шапке |
| Пустые имена устройств Windows | `nul.js` создать нельзя | в фикстурах имена `nul`/`con`/`aux` не используются |

**Осознанные отличия** (полный список в `docs/BAT-PORT.md` §4): ASCII-справка вместо
UTF-8-буллетов; время правки через PowerShell, а без него — не восстанавливается;
пути со знаком `!` не поддерживаются; около секунды на 100 КБ; смещение NUL
сообщается номером строки дампа.

## 7. Что осталось

1. **Индексация `.ps1`/`.sh`/`.bat` в RAGRAF невозможна** без расширения
   `LANG_BY_EXT` (`config.py`) и добавления текстового пути для этих языков. Раз это
   инфраструктура RAGRAF, а не этого проекта, — вынесено как предложение, не как
   правка: без тестов RAGRAF менять её нельзя.
2. **`package.json` запрещает установку на Windows** полем `os`, хотя в пакете лежат
   `.ps1` и `.bat`. Не менялось (AGENTS.md §9 п.1).
3. **Отсутствующий аргумент-файл** даёт `Access errors: 1`, но код выхода `0` в режиме
   явных файлов — воспроизведено на обеих реализациях, поведение сохранено.
4. **Гонки параллельных прогонов** по одному файлу не проверены на живой нагрузке
   (AGENTS.md §10). Имена бэкапов уникальны по идентификатору прогона, но операции
   не сериализованы.
5. **`trailing_cr` для `.bat`** проверен только на одно-, двух- и многострочных
   файлах; отдельного случая «файл, где единственный CR стоит ровно на границе
   16-байтового дампа и одновременно в конце», в наборе нет — покрыт косвенно
   фикстурой `boundary_cr.txt`.
