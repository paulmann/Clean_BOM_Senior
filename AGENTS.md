# Проект: Clean_BOM_Senior

Инструкции для агента, работающего в этом каталоге. Заполнены по фактам, снятым
read-only сканером (`C:\AutoClaw\Agents.Creator\Invoke-ProjectScan.ps1`) и разбором
кода; всё, что требует решения человека, помечено `TODO:`.

---

## 1. Что это за проект

Две реализации одного инструмента: удаление невидимого UTF-8 BOM и нормализация
Windows CRLF в файлах `.php .css .js .txt .xml .htm .html`.

| Файл | Что это |
|---|---|
| `clean-bom-senior.sh` | эталон: POSIX shell, v2.07.0, 687 строк, зависимости — find/sed/od/grep/stat/mv/cp/touch/chown/chmod |
| `clean-bom-senior.ps1` | порт на PowerShell 7.6, поведение сверено с эталоном байт-в-байт |
| `clean-bom-senior.bat` | порт на cmd.exe (Windows 10/11) для хостов без Git Bash и без PowerShell: байты через `certutil` |
| `tests/differential.ps1` | дифференциальный тест `.ps1` ↔ `.sh`: сырые байты, две копии набора, сравнение файлов и кодов выхода |
| `tests/cli-contract.ps1` | контракт CLI порта: разбор аргументов, детекция бинарности, форма путей в логе |
| `tests/bat-differential.ps1` | дифференциальный тест `.bat` ↔ `.ps1` (и ↔ `.sh`), 15 фикстур, сырые байты |
| `docs/BAT-PORT.md` | устройство batch-порта: шестнадцатеричный фильтр, ловушки cmd, осознанные отличия |
| `bin/bom.js` | npm-обёртка: `spawnSync('bash', [script, ...args])` |
| `bin/postinstall.js` | `chmod 755` на `.sh` после установки |
| `package.json` | npm-пакет `clean-bom-senior` 2.7.0, `os: [linux, darwin]`, `files` включает оба скрипта |

Стек: shell (эталон) + Node (обёртка) + PowerShell 7.6 (порт).
Документация — английский (`README.md`). Язык новых документов и комментариев:
английский для кода в репозитории, русский для внутренних заметок этого набора.

## 2. Роль

Работай как **инженер по миграции и паритету инструментов командной строки**:
поведенческий порт CLI между средами, побайтовая эквивалентность, коды выхода,
сохранение метаданных файлов.

Что здесь считается провалом:
- порт, который «работает», но даёт другие байты, чем эталон;
- испорченный файл, который никто не заметил (инструмент правит файлы на месте);
- заявленный код возврата, не совпадающий с фактическим;
- документация, обещающая то, чего код не делает.

## 3. Команды

```powershell
# версия и справка (stdout)
pwsh -NoLogo -NoProfile -NonInteractive -File .\clean-bom-senior.ps1 --version
pwsh -NoLogo -NoProfile -NonInteractive -File .\clean-bom-senior.ps1 --help

# просмотр без изменений
pwsh -NoLogo -NoProfile -NonInteractive -File .\clean-bom-senior.ps1 --dry-run

# обработка: рекурсивно от текущего каталога
pwsh -NoLogo -NoProfile -NonInteractive -File .\clean-bom-senior.ps1

# только конкретные файлы
pwsh -NoLogo -NoProfile -NonInteractive -File .\clean-bom-senior.ps1 a.php b.js

# batch-порт (cmd.exe, когда нет ни PowerShell 7, ни Git Bash)
clean-bom-senior.bat --dry-run
clean-bom-senior.bat a.php b.js

# эталон для сравнения (Git Bash)
& 'C:\Program Files\Git\bin\bash.exe' -c "cd /c/путь && bash clean-bom-senior.sh"
```

```powershell

# контракт CLI порта
pwsh -NoLogo -NoProfile -NonInteractive -File .\tests\cli-contract.ps1

```

`php`, `node` и Git Bash в этой среде есть; `composer` нет.

## 4. Незыблемые инварианты

1. **Побайтовый паритет с `.sh`.** Для одного и того же входа порт и эталон дают
   одинаковые байты. Исключения перечислены в разделе 6 и только они.
2. **Правится только то, что грязно.** Файл без BOM и без CRLF не перезаписывается:
   его mtime не меняется.
3. **Ломать файл запрещено.** Запись идёт через временный файл; при сбое —
   восстановление из бэкапа. Файл с NUL-байтом не трогается (порт; см. раздел 6).
4. **Коды выхода совпадают с эталоном:** 0 — успех, 1 — были ошибки обработки,
   2 — неизвестный флаг, 3 — недоступен временный каталог.
5. **Запуск только в изолированном каталоге.** Без аргументов инструмент
   рекурсивно обрабатывает текущий каталог; в чужом проекте это правка чужих файлов.
6. **`--no-bom-clear` и `--no-rn-normalize` независимы** и реально отключают
   соответствующую операцию (в порте; эталонный `.sh` под MSYS делает это неверно).
7. **Trailing CR в конце файла** удаляется (sed `$` совпадает и с концом буфера);
   одиночный CR внутри строки сохраняется. Проверено на обеих реализациях.

## 5. Как проверять

Дифференциальный тест — единственный надёжный способ: он создаёт фикстуры сырыми
байтами, прогоняет обе реализации на копиях и сравнивает результат. Тест лежит в
репозитории и запускается так:

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -File .\tests\differential.ps1
```

Ожидаемый результат `tests/differential.ps1`: `shell exit: 0   port exit: 0`,
`identical: 14 / 14 compared`, `leftover backups - shell: 0  port: 0`, `parity verified:
identical bytes and identical exit codes`, код возврата 0. Тест возвращает 1 при любом
расхождении байтов, кодов выхода, при оставленном бэкапе и при невоспроизведённом
осознанном отличии; 2 — если не найдены порт, эталон или Git Bash.

Ожидаемый результат `tests/cli-contract.ps1`: `assertions checked: 15   failures: 0`,
`CLI contract holds`, код возврата 0. Тест закрывает три дефекта, найденных аудитом
5 октября 2026: одиночный `-` как неизвестная опция, NUL-байт за пределами первого
блока чтения, абсолютные пути в логе вместо `./имя`. Проверено, что тест падает на
инжектированном дефекте.

Ожидаемый результат `tests/bat-differential.ps1`: `identical: 15 / 15 compared`,
`leftover backups in the batch tree: 0`, `batch parity verified`, код возврата 0.
Расхождение с `.sh` по файлу с NUL-байтом — осознанное (§6) и утверждается, а не
сравнивается. Если Git Bash не найден, тест прямо сообщает, что сравнение с эталоном
пропущено.

Аудит и отчёт об использовании RAGRAF — `docs/RAGRAF-REPORT.md`.

Изоляция: фикстуры создаются в свежем каталоге `%TEMP%`, каждая реализация
запускается с рабочим каталогом внутри своей копии набора, копия эталона берётся из
временного каталога. Репозиторий прогон не меняет.

Фикстуры (17): только BOM; BOM+CRLF; CRLF без BOM; уже чистый файл (не должен
перезаписываться); пустой файл; файл из одного BOM; смешанные окончания; одиночные
CR; CR в конце файла; файл без завершающего перевода строки; неподдерживаемое
расширение; расширение в верхнем регистре; вложенный каталог; CRLF за пределами
первых 1024 байт; BOM не в начале файла; файл с NUL-байтом (`[EXPECTED]`, см. §6);
файл для отдельного прогона с `--no-rn-normalize`.

Кроме сравнения байтов тест проверяет осознанные отличия (§6): mtime сохранён,
`vendor/` и `node_modules/` и `.git/` не переписаны (эталон их переписывает),
справка называет `clean-bom-senior.ps1`, относительный аргумент-файл не даёт ложного
`Cannot read file`.

Сравниваются 14 файлов: `empty.xml` и `bom_only_empty.htm` исключены эталоном
(`find -size +0c` их не выбирает, а после очистки файл из одного BOM исчезает из
списка), `binary_nul.js` — осознанное расхождение и проверяется как таковое.

Проверка самого теста (обязательна после правки теста): скопировать репозиторий во
временный каталог, внести дефект в копию порта (например заменить
`if ($atEndOfFile -or $beforeLf) { continue }` на `if ($beforeLf) { continue }`) и
убедиться, что тест даёт `[DIFF]` и код возврата 1. Тест, который не падает на
дефекте, ничего не проверяет.

## 6. Отличия от эталона (осознанные)

| Что | `.sh` | `.ps1` | Почему |
|---|---|---|---|
| mtime после правки | перезаписывается на время копирования (`touch -r` ссылается на свежий бэкап) | сохраняется исходный | README обещает «Timestamps preserved» |
| `--no-rn-normalize` | CRLF всё равно убираются (MSYS sed режет CR при чтении) | флаг действительно отключает нормализацию | заявленный флаг должен работать |
| метаданные | uid/gid/mode через `chown`/`chmod` | ACL и атрибуты файла | POSIX-режимов в Windows нет |
| файл с NUL-байтом | перезаписывается (риск порчи) | пропускается, считается skipped | не портить бинарные данные |
| обход каталогов | заходит в `vendor/`, `.git/`, `node_modules/` | эти каталоги пропускаются | иначе правит чужой код в репозитории |
| код выхода 3 | недоступный `TMPDIR` даёт 3 сразу | `[IO.Path]::GetTempPath()` проверяет среду и откатывается на рабочий каталог, поэтому код 3 достижим только при реально нерабочем temp-каталоге | окружения автоматизации часто не имеют `TMPDIR`/`TMP` |
| текст справки | в `USAGE` стоит `clean-bom-senior.sh` | `clean-bom-senior.ps1` плюс блок PowerShell-замечаний | в подсказке должно быть имя запущенного файла |
| путь в логе | `./имя` (обход через `find .`) | `./имя` для рекурсивного обхода, аргумент — verbatim | до 2026-10-05 порт печатал абсолютный путь |
| счётчик `size_errors` | инициализируется и печатается, никогда не увеличивается | строка сохранена ради паритета, значение 0 | недостижим в обеих реализациях |

### Третья реализация: `clean-bom-senior.bat`

Отличия batch-порта от `.ps1` и `.sh` — в `docs/BAT-PORT.md` §4. Кратко: справка только
ASCII (кодовая страница консоли); время правки восстанавливается через PowerShell, а
без него — не восстанавливается, о чём печатается предупреждение; пути со знаком `!`
не поддерживаются; около секунды на 100 КБ; смещение NUL сообщается строкой дампа.
Файловое содержимое — байт-в-байт как у `.ps1`, подтверждено `tests/bat-differential.ps1`.

Замеры для строк 1, 2, 6: mtime — эталон `23:39:22.659 → 23:39:25.077`, порт
`23:39:22.659 → 23:39:22.659`; `--no-rn-normalize` на файле `EF BB BF 61 0D 0A 62 0D 0A`
— порт оставляет CRLF, эталон их убирает; `TMPDIR=/nonexistent-xyz` — эталон
`exit 3`, порт `exit 0`.

Отличия 1, 2, 3, 5, 7 — не компромисс, а исправление: `.sh` обещает то же самое
поведение в своём README и не выполняет его. Отличия 4 и 6 — решения по безопасности.

Покрытие отличий тестом (§5): строки 1, 2, 5, 7 и 4 проверяются прямыми assertion'ами
(сохранённый mtime, сохранённые CRLF под `--no-rn-normalize`, нетронутые
`vendor/`/`node_modules/`/`.git/`, имя файла в справке, пропуск бинарного файла);
строки 3 и 6 — по своей природе не воспроизводимы на обеих реализациях в одной
ОС (POSIX-режимов на Windows нет; код 3 у порта недостижим через переменные среды),
поэтому они зафиксированы как замеренные факты с командами в этом файле.

Все остальные наблюдаемые свойства — формат вывода, тексты сообщений, итоговая
статистика, коды выхода — повторяют эталон и попадают в сравнение в §5.

## 7. Ловушки (проверены на практике)

**PowerShell:**

- `exit (Функция)` теряет текст: функция, которая пишет в stdout **и** возвращает
  код, отдаёт массив, и строки исчезают. Сначала присвой, потом `exit`.
- Возврат коллекции разворачивается: `List` из одного элемента приходит как строка,
  пустой — как `$null`, и `.Count` падает под `Set-StrictMode`. Нужен префикс `,`.
- `continue` внутри `switch` продолжает `switch`, а не цикл: парсер аргументов на
  `switch` обрабатывал каждый аргумент дважды.
- Оператор `-eq` не учитывает регистр, поэтому `-v` совпадал с `-V`. Для флагов
  нужен `-cin` / `-ceq`.
- `-Filter` в `Get-ChildItem` матчит по 8.3-именам: `*.bak.*` даёт лишние попадания.
  Проверяй регулярным выражением по `Name`.
- **`[System.IO]` и провайдерный путь — разные вещи.** `Set-Location` меняет
  местоположение провайдера, но `[System.IO.File]::Open('a.php')` резолвит
  относительный путь от рабочего каталога **процесса**. Замерено: при
  `Set-Location` в песочницу и рабочем каталоге процесса в другом месте явный
  относительный аргумент давал `Cannot read file`, хотя `Test-Path` тот же файл
  находил. Лечение: выровнять рабочий каталог процесса по `Get-Location` в начале
  скрипта (в `clean-bom-senior.ps1` — перед `Invoke-Main`) и якорить путь
  (`[IO.Path]::GetFullPath`) перед каждым вызовом `[System.IO]`.
- **Windows резервирует имена устройств.** Файл `nul.js` создать нельзя: запись
  молча уходит в устройство, и файла в каталоге не появляется. В фикстурах не
  использовать имена `nul`, `con`, `aux`, `com1`… с любым расширением.
- **`[IO.Path]::GetTempPath()` кэширует среду.** Переменные `TMP`/`TEMP`, заданные
  внутри уже запущенного процесса, на temp-путь не влияют — проверять только через
  наследование переменной дочерним `pwsh -Command`.
- **Вывод и код возврата вместе.** Функция, которая пишет в stdout и возвращает код,
  отдаёт массив; `exit (Invoke-Main ...)` потеряет текст справки. Сначала присвоить,
  потом `exit`.

**Shell (эталон):**

- `sed` под MSYS работает в текстовом режиме и срезает CR при чтении — отсюда
  дефект `--no-rn-normalize`.
- Детекция CRLF смотрит только первые 1024 байта: CRLF дальше в файле не находится.
- BOM ищется строго в первых трёх байтах; BOM в середине файла не удаляется, но
  CRLF в таком файле нормализуются.
- Счётчик `ERROR_TYPES["size"]` в эталоне всегда 0: ни один путь его не увеличивает
  (`clean-bom-senior.sh:104` — инициализация, `:538` — печать; увеличения нет).
  Заявленный лимит 100 МБ реализован только через `find -size`.
- `cleanup()` вызывает `find "$TEMP_DIR"` **без кавычек** (`clean-bom-senior.sh:111`):
  при `TMPDIR` с пробелом временные файлы не удаляются. Замерено:
  `find $d …` при пути с пробелом → `rc=1`, в кавычках → `rc=0`. Не исправлено
  сознательно (см. таблицу отличий).

**cmd (batch-порт):**

- `.bat` **обязан** быть с CRLF: с LF-переводами `cmd` не исполняет файл вовсе —
  `exit 255` и пустой вывод. Замерено. Этот инструмент сам его не чистит.
- Скобки в тексте внутри `if ( … )` ломают блок: сначала молчаливое прекращение
  обработки, затем `exit 255`. Экранирование `^(` `^)` не помогает. Сообщения со
  скобками выводятся из отдельных меток.
- `set /a` внутри `if`-блока даёт `* was unexpected at this time`: переменные
  подставляются до разбора блока. Вся арифметика вынесена в метки с `call`.
- Подстановка по **пустому** значению не выполняется: `set "C=" & set "T=!C:~6!"`
  даёт `T=[~6]` (литерал), а `set "B=" & set "B=!B:0d0a=0a!"` — `B=[0d0a=0a]`.
  Из-за этого ломались файлы из одного BOM — дважды.
- `for /r *.htm` матчит и `.html` по 8.3-имени (`.html` → `.HTM`) — тот же класс,
  что `Get-ChildItem -Filter` в PowerShell. Список без `*.html` плюс проверка
  расширения на каждый файл.
- `%*` внутри вызываемой метки содержит её собственные аргументы — нужен `%~2`.
- `copy /b` сохраняет атрибуты и время создания приёмника, но **перезаписывает время
  правки**; `move` в тот же путь — то же. Поэтому время восстанавливает PowerShell.
- `pwsh -Command "& script.ps1 <args>"` **искажает аргументы и код выхода**: `-`
  доходит пустой строкой, а код 2 превращается в 1. Тесты запускают порт только
  через `pwsh -File …` или `ProcessStartInfo.ArgumentList`.
- Пустые имена устройств Windows: `nul`, `con`, `aux`, `com1`… — в фикстурах не
  использовать.

**Общее:**

- Запуск без аргументов = рекурсивный обход **текущего каталога**. Всегда
  переходи в изолированный каталог перед прогоном.
- Аргумент-каталог не поддерживается: `script.sh nested` даёт `File not found`.
- Отсутствующий путь в режиме явных файлов даёт `Access errors: 1`, но код выхода
  остаётся 0 — а в рекурсивном режиме та же ошибка даёт 1.

## 9. Решения по открытым вопросам

Решено 2026-10-02, все четыре пункта закрыты:

1. **Порт остаётся отдельным.** `.sh` — эталон и npm-обёртка (`bin/bom.js` продолжает
   вызывать bash, `os: [linux, darwin]` не меняется); `.ps1` — путь для Windows без
   Git Bash. Общего CLI-диспетчера пока нет, он в roadmap. Причина: замена `.sh`
   ломает существующие установки, а паритет нужен именно для того, чтобы обе
   реализации существовали одновременно.
2. **Тест переехал в репозиторий** — `tests/differential.ps1`, запуск и ожидаемые
   числа в §5. Каталог `.staging` больше не нужен (файл там можно удалить вручную).
3. **`.ps1` включён в npm-пакет:** добавлен в `package.json` → `files`, в `keywords`
   добавлены `powershell` и `windows`.
4. **`.sh` не чинится.** Расхождения `.sh` с собственным README (mtime,
   `--no-rn-normalize`, неиспользуемый счётчик `size`) задокументированы в `README.md`
   как таблица осознанных отличий и проверяются тестом. Правка `.sh` сломала бы
   эталон, на котором основано доказательство паритета; `LANG`/MSYS-дефект `sed`
   без изменения окружения не устраняется. При этом надо помнить: README заявляет
   «Timestamps preserved», а на `.sh` это неверно — держать это отражённым в
   таблице отличий, а не прятать.

## 10. Что осталось

- **RAGRAF не разбирает `.ps1`, `.sh` и `.bat`.** Карта `LANG_BY_EXT`
  (`C:\AutoClaw\RAGRAF\src\ragraf\config.py`) содержит только
  `php phtml inc md sql css htm html js mjs`, а разбор деревом идёт только для
  `php/css/html` (`indexer.py:309`); всё остальное отбрасывается как
  `skipped_not_included`. Следствие: статические операции (`symbol`, `code`,
  `callers`) к этому проекту неприменимы, и факты по коду добываются замерами со
  ссылками `файл:строка`. Подробности — `docs/RAGRAF-REPORT.md` §1.
- Не проверено на живой Windows-нагрузке: гонки параллельных прогонов по одному
  файлу (бэкап `<file>.bak.<pid>` уникален по pid, но два прогона на одном файле
  не сериализованы).
- Счётчик `ERROR_TYPES["size"]` в порте сохранён ради паритета вывода, но
  недостижим: переполнение по размеру даёт skipped, а не ошибку (как и в эталоне).
- `.ps1` не запускается на PowerShell 5.1 и не должен: файл без BOM с не-ASCII
  текстом в 5.1 читается как ANSI. Не подавать его в очистку для 5.1-совместимости.
- `clean-bom-senior.bat` не имеет случая «единственный CR ровно на границе
  16-байтового дампа и одновременно в конце файла»: границу покрывает
  `boundary_cr.txt`, конец файла — `trailing_cr.htm`, пересечение — нет.
- В `clean-bom-senior.bat` производительность — около секунды на 100 КБ
  (построчный цикл cmd). Для деревьев исходников приемлемо, для файлов в мегабайты
  — нет; в таких случаях нужен `.ps1`.
- `package.json` содержит `"os": ["linux", "darwin"]`, то есть установка пакета на
  Windows запрещена, хотя в пакете есть `.ps1` и `.bat`. Не менялось (см. §9 п.1).
